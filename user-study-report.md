# In-Person User Study and Functionality Review

## Overview

I conducted three separate in-person user studies to evaluate the functionality and usability of my generative joke application. During each session, I directly observed the participant as they interacted with the application in real time. The focus of this study was on usability, navigation, clarity, responsiveness, and overall functionality rather than on the quality of the generated jokes.

---

# User Study 1

## 1. User Information

- **Relationship to user:** Classmate
- **Has the user used the app before?** None
- **Experience with similar applications:** Moderate. The user had used apps with voting interfaces and image-based social content before, but had not used this specific application.

## 2. Observation Context

- **Location:** Butler Library study area
- **Device used:** 13-inch MacBook Air
- **Instructions given:** I asked the user to open the application, explore it naturally, and try to understand what it does without much help from me. I then asked them to try viewing captions, signing in, and rating content.
- **Task style:** Semi-structured. I let the user explore freely at first, then asked them to complete a few specific actions.

## 3. Three Things the User Liked (Functionality Only)

1. The user said the navigation was easy to understand because the main sections were clearly separated.
2. The user liked that the app did not feel cluttered and that each page had a distinct purpose.
3. The user found the voting interface straightforward once they reached it because the interaction was focused and simple.

## 4. Three Areas for Improvement

1. The user was not immediately sure what the recommended first step was when landing on the home page.
2. The difference between browsing captions and actively rating them was not completely obvious at first.
3. The upload feature seemed more advanced than the other parts of the application and could use clearer instructions.

## 5. Observed Friction or Confusion

- The user paused for several seconds on the landing page before clicking anything.
- The user asked whether they were supposed to sign in immediately or browse first.
- The user clicked on the captions section first, then later realized that rating was a separate workflow.
- The user needed a moment to understand whether the upload page was part of the normal user flow or a more specialized feature.

## 6. Behavioral Observations

- The user first looked at the center of the landing page and read the large title and main buttons.
- They moved cautiously and read page labels before clicking.
- They explored the captions page before attempting login.
- They became more confident when they reached a page with one clear next step.
- They preferred to understand the structure of the app before interacting deeply with it.

## 7. User Quotes

- “I get the sections, but I’m not sure where I’m supposed to begin.”
- “This part is actually really simple once I got here.”
- “I thought browsing and rating were the same thing at first.”

# User Study 2

## 1. User Information

- **Relationship to user:** Friend
- **Has the user used the app before?** Minimal
- **Experience with similar applications:** High. The user regularly uses apps with swipe, vote, and account-based interaction patterns.

## 2. Observation Context

- **Location:** Residence hall common room
- **Device used:** iPhone 14
- **Instructions given:** I asked the user to try the application on mobile and narrate what they thought each page was for. I told them to attempt normal use without asking for help unless they got stuck.
- **Task style:** Mostly free exploration with a few prompts to visit core features.

## 3. Three Things the User Liked (Functionality Only)

1. The user said the app looked organized and easy to scan on mobile.
2. The user liked that the sidebar and major labels made it easy to understand that the app had multiple sections.
3. The user appreciated the visible loading and status feedback because it made the app feel responsive.

## 4. Three Areas for Improvement

1. The user expected some actions from the captions page that were actually part of the ratings flow.
2. The sign-in requirement was not obvious until the user tried to interact more deeply with the app.
3. Some pages would benefit from a brief one-sentence explanation at the top so the user immediately knows what the page is for.

## 5. Observed Friction or Confusion

- The user tapped through pages quickly and made assumptions before reading the explanatory text.
- They expected to be able to rate directly from the browsing experience.
- They hesitated when redirected through the sign-in flow and briefly wondered whether anything had gone wrong.
- They asked whether uploading was intended for all users or only certain users.

## 6. Behavioral Observations

- The user was confident and exploratory from the start.
- They relied more on visual structure and button labels than on reading text carefully.
- They tapped into multiple sections quickly to build a mental map of the app.
- They were comfortable recovering from mistakes, but still wanted more guidance about the intended user journey.
- They adapted quickly once they understood that some actions required authentication.

## 7. User Quotes

- “It looks clean, but I’m guessing a little about the order.”
- “I thought I could vote from here.”
- “The feedback messages are helpful because I know the app is doing something.”

# User Study 3

## 1. User Information

- **Relationship to user:** Cousin
- **Has the user used the app before?** None
- **Experience with similar applications:** Low. The user was generally comfortable with websites and apps, but not with tools that involve multiple steps like logging in, uploading, and rating content.

## 2. Observation Context

- **Location:** Apartment living room
- **Device used:** Windows laptop
- **Instructions given:** I asked the user to use the app independently and tell me what they believed each section was designed to do. I did not guide them unless they seemed stuck for a long time.
- **Task style:** Independent exploration with observation-focused note-taking.

## 3. Three Things the User Liked (Functionality Only)

1. The user said the application looked polished and felt more complete than a rough prototype.
2. The user found it easy to move between sections without feeling lost.
3. The user liked that the rating screen focused attention on one item at a time instead of overwhelming them with too many options.

## 4. Three Areas for Improvement

1. The home page should explain the app’s purpose and expected flow more clearly.
2. The app should more explicitly indicate which actions are public and which require login.
3. The upload and generation process should include clearer step-by-step instructions for first-time users.

## 5. Observed Friction or Confusion

- The user initially assumed every page would work in the same way and be equally interactive.
- They did not realize at first that login was tied to certain features.
- They spent longer on the upload page than on the other pages because they were trying to infer what would happen after uploading.
- They looked for a short onboarding explanation but did not find one.

## 6. Behavioral Observations

- The user looked first at navigation labels rather than descriptive text.
- They clicked through all major pages before deciding where to spend time.
- They hesitated when a page required them to infer a workflow on their own.
- They seemed more comfortable when the interface clearly narrowed their choices.
- They did not get completely stuck, but they needed more interpretation help than the other two users.

## 7. User Quotes

- “It looks nice, but I want a little more direction.”
- “I’m not sure which parts are just browsing and which parts are actual actions.”
- “This page seems important, but I don’t totally know what I’m supposed to do first.”

# Final Summary

## What I Learned from Observing Users

Watching users interact with the application in person showed me that the app is functional and visually organized, but users still need more guidance to understand the intended workflow. All three users were able to identify that the app had separate sections for browsing, rating, signing in, and uploading. However, multiple users were uncertain about where to begin and how the different sections connected to each other.

I also learned that users respond well when a page presents one clear next action. Pages with a focused interaction, such as the rating flow, were easier for users to understand. Pages that required more interpretation, such as the landing page or upload flow, created more hesitation.

## Things I Found Surprising

One surprising result was that users generally understood the navigation faster than I expected. They were able to identify the major sections of the app relatively quickly. However, even when they understood the structure, they still did not always understand the intended order of use.

Another surprising result was that the most consistent friction did not happen during the rating interaction itself. Instead, confusion happened earlier, when users were trying to understand the difference between browsing captions, signing in, and rating.

## Patterns Noticed Across Multiple Users

1. All three users hesitated on the landing page before deciding what to do first.
2. More than one user confused browsing captions with rating captions.
3. More than one user wanted clearer explanation of which features required authentication.
4. All three users became more confident when they reached an interface with a single obvious next action.
5. Multiple users wanted more guidance on the upload/generation feature.

## At Least Three Specific Improvements I Plan to Make

1. **Add a clearer onboarding message on the home page.**  
   I plan to add a short explanation that tells users what the app does and suggests a recommended first step.

2. **Clarify which features require sign-in.**  
   I plan to label features like rating and uploading more clearly so users know in advance which actions require authentication.

3. **Add short instructional text to each major page.**  
   I plan to include one-sentence descriptions at the top of pages like Captions, Ratings, and Upload to explain their purpose.

4. **Make the app flow more explicit.**  
   I plan to guide users through a clearer sequence such as Browse → Sign In → Rate or Upload, so the relationship between features is easier to understand.

5. **Improve the upload flow with more visible step-by-step guidance.**  
   I plan to make the process easier for first-time users by showing clearer instructions and progress explanations.

## Closing Reflection

Overall, these user studies showed that the application is usable and functionally solid, but the user experience would improve with clearer guidance, more explicit workflow communication, and stronger explanation of authentication requirements. Observing real users in person was especially helpful because it revealed moments of hesitation and uncertainty that would have been easy to miss through self-testing alone.
